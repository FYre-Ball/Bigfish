# Task Handover Snapshot（任务交接快照）

长期开发任务无法保证在单次会话内完成时，用统一快照目录在断点处留下结构化交接信息,让新会话能**选择已有快照**并接力推进，避免从头返工。

**核心原则:** 快照是可复制粘贴、可直接接手的事实摘要,新会话严格按快照的「下一步目标 + 禁止事项」接力,禁止重新做已完成的部分。

## 快照存储目录

所有快照持久化到**统一目录**,新会话靠它扫描并选择已有快照：

- 默认目录：`D:\Bigfish\.handover-snapshots\`
- 每次生成在该目录新建一个 `.md` 文件
- 文件名格式：`YYYYMMDD-HHMMSS-<简述>.md`(时间戳保证唯一、可排序)
  - 例如 `20260712-154320-任务交接-DeepSeek插件.md`
- 若无法写默认目录(只读/受限)，改用会话当前工作目录下 `.handover-snapshots\`
- 若用户指定了其它目录，以用户指定为准

本技能自带脚本 `scripts/handover.mjs`,封装「列出快照 / 读取快照 / 写入快照」三类确定性操作(见「脚本用法」)。

## 模式 A：生成快照（写侧）

### 触发条件 —— 满足任意一条立即生成快照

1. 当前对话轮次 ≥ 120 步
2. 收到系统提示步数即将耗尽、上下文窗口快要占满
3. 出现输出乱码、工具大量返回日志造成上下文膨胀
4. 用户发送停止指令，要求暂停工作
5. 你预判剩余工作量无法在本轮会话剩余步数内做完

> 注意：如果步数充裕、任务远未到上限，则正常推进开发——**不需要**每次都输出快照，只在触发条件出现时生成。

### 生成流程

1. 用 `scripts/handover.mjs write` 把快照写入统一目录(或直接写 `.md` 文件)
2. 文本内容严格按下方「强制结构」模板
3. 写入后把完整快照内容在回复中贴出(便于复制粘贴)
4. 生成完毕后**主动暂停本轮工作**,不要再继续向下执行开发工作

### 强制结构模板

ALWAYS 使用这个精确结构(`<...>` 为必填占位，不留空)：

```markdown
# 任务交接快照
- 会话标识: <会话/任务名>
- 生成时间: <YYYY-MM-DD HH:MM>
- 目标: <本轮要完成的目标，一句话>

## 当前进度
<已完成到什么程度，用列表列出已落地的事实/文件>

## 下一步目标
<接手后要做的第一件事起，按优先级列出>
1. <...>
2. <...>

## 禁止事项
- 不要从头返工（已完成部分直接沿用）
- <其它明确禁止的操作/假设>

## 关键上下文
<接手必需的事实：涉及的文件路径、用到的命令、环境变量、已确认的技术决策、DSH/桌面壳关键事实等>

## 风险与注意
<接手时可能踩的坑、未验证的假设、遗留问题>
```

**写作约束：**
- 简洁、事实化，不带冗余推理文字
- 快照本身可以直接复制粘贴到新会话就能接手工作
- 目标、进度、上下文都要落到具体文件路径和命令，不得含糊

## 模式 B：选择已有快照接力（读侧）

在**新会话**中，当用户要求继续/接力/接手/恢复之前的工作时：

### 流程

1. **扫描目录**：列出统一目录下全部快照，按时间倒序(最新在前)
   - 用 `scripts/handover.mjs list`，或 `glob` 匹配 `**/.handover-snapshots/*.md`
2. **让用户选择**：把每个快照的「文件名 + 头部概要(会话标识/目标/生成时间)」列给用户,让用户确认选哪一个;若只有一个候选可直接确认
   - 需要时先用脚本读文件头几行做概要，再让用户选定
3. **完整读取快照**:对用户选定的快照,必须**完整读取全文**(不止概要)
4. **严格遵守并接力**:
   - 先完整遵守快照里的「禁止事项」
   - 从「下一步目标」所列的第一项开始直接推进
   - **禁止从头返工**已完成的部分;用「关键上下文」里的事实继续,不重复学习/不重复已确认的决策
5. 开始推进后,正常按新的目标任务工作,直到本轮再次触发模式 A 条件时生成新的快照

### 找不到快照时

- 如果目录为空或没有匹配的快照,主动告知用户"未找到可接力的快照",并询问快照可能在哪个位置,或确认是否从零开始。

## 脚本用法

`scripts/handover.mjs` 提供确定性操作,优先用它代替手写命令/手工枚举:

```bash
# 列出全部快照(时间倒序,最新在前)
node scripts/handover.mjs list [--dir 目录]

# 读取某个快照全文
node scripts/handover.mjs read <快照文件路径>

# 写入一个新快照(从 stdin 读内容)
node scripts/handover.mjs write --name "简述" [--dir 目录] < content.md
```

- `--dir` 缺省为 `D:\Bigfish\.handover-snapshots\`
- `write` 自动生成 `YYYYMMDD-HHMMSS-<简述>.md` 文件名

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| 快照内容写成长篇叙述/推理 | 只写事实、路径、命令，直接可接手 |
| 新会话拿到快照却从头重新做 | 严格按「禁止事项」+「下一步目标」接力，禁止返工 |
| 不把快照写入统一目录，只贴文本 | 必须持久化到统一目录，否则新会话无法选择 |
| 新会话只读概要就开始做 | 先完整读取所选快照全文再动工 |
| 新会话没有让用户选择就直接用最早/最新快照 | 让用户确认选哪一个，避免接错任务 |
